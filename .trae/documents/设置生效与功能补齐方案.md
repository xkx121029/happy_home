# 设置生效与功能补齐方案

## 背景

用户要求「加更多的设置，更多的功能」。审计后发现，这个项目**不缺设置项，缺的是让设置生效**：

| 现状 | 数据 |
|---|---|
| `ALLOWED_SETTING_KEYS` 白名单键数 | 66 |
| `Settings.jsx` 标签页 / 表单字段 | 13 个 / 约 60 个 |
| **真正被代码消费的键** | **约 12 个**（其中 6 个是 SMTP） |
| 只写不读的键 | 约 55 个 |

在这个基础上继续堆设置，只会把死字段从 55 个变成 100 个。所以本方案的重心是「接线 + 收敛」，而不是「新增表单」。

另外三处经核实的具体缺陷：

1. **定时发布有 8 小时时区 bug**。调度器已存在（`backend/server.js:43-75`），但前端 `datetime-local` 写入的是本地时间 `YYYY-MM-DDTHH:mm`，后端用 `datetime('now')`（UTC）比较，Asia/Shanghai 下会提前 8 小时触发。
2. **修订功能是完全空的**。`revisions` 表建了，但全仓**没有任何代码写入**，没有任何端点；`src/pages/Revisions.jsx` 里是 `const postRevisions = []` 加 `alert('修订功能暂未实现')`。
3. **RSS / sitemap 不存在**，且没有任何 XML 生成工具可复用。

以及两个连带发现：

- **`prose` 类是死的**：`@tailwindcss/typography` 未安装（`tailwind.config.js` 的 `plugins: []`），但 `prose prose-lg dark:prose-invert` 在 5 个文件里出现 13 次。**文章正文目前完全没有排版样式**。
- **同一个功能存在互不通气的多个入口**：自定义 CSS 有 3 条链路、SEO 有 2 套、Analytics 有 2 套、社媒分享是 localStorage 与白名单脱节。

## 已确认的用户决定

- 空概念设置项（压缩 / 缓存 / Gzip / SSL / 懒加载 / 调试等约 10 项）→ **直接删除**
- 前台公开站点 → **跟随后台主题**
- ESLint 83 项问题 → **全部清掉**

## 阶段 3：界面统一（全站 token 化）

52 个文件、约 3950 处硬编码颜色类。

### 3.1 一次性 codemod（用完即删）

写 `scripts/codemod-tokens.mjs`，**默认 dry-run**，逐文件输出 unified diff + JSON 报告，`--apply` 才写盘。

作用域界定是关键：只重写 `className=` 属性值内部的字符串字面量段（含模板串里 `${}` 之外的段）。因为作用域被限定在 className 内，`alert()` 文案、注释、`CustomCSS.jsx` 的 CSS 文本天然碰不到，不需要额外黑名单。文件级排除 `src/theme/palettes.js`、`src/theme/apply.js`、`src/pages/CustomCSS.jsx`。

映射表（**已修正一处陷阱**）：

| 旧 | 新 |
|---|---|
| `bg-white` / `dark:bg-gray-800` | `bg-surface` |
| `bg-gray-50` / `dark:bg-gray-900` | `bg-bg` |
| `bg-gray-100` / `dark:bg-gray-700` | `bg-surface-2` |
| `hover:bg-gray-*` | **`hover:bg-line/60`** |
| `text-gray-900` / `dark:text-white` | `text-fg` |
| `text-gray-700` / `dark:text-gray-300` | `text-fg` |
| `text-gray-500|400` / `dark:text-gray-400` | `text-muted` |
| `border-gray-100|200` / `dark:border-gray-600|700` | `border-line` |
| `divide-gray-*` | `divide-line` |
| `bg-blue-500 text-white hover:bg-blue-600` | `bg-accent text-accent-fg hover:bg-accent-700` |
| `bg-blue-50 dark:bg-blue-900/30 text-blue-600` | `bg-accent/12 text-accent` |
| `border-blue-500` / `focus:ring-blue-500` | `border-accent` / `focus:ring-accent` |
| 开关关闭态 `bg-gray-300 dark:bg-gray-600` | `bg-line` |
| `bg-green-* text-green-*` | `bg-success/12 text-success` |
| `text-red-*` / `bg-red-*` | `text-danger` / `bg-danger/12` |
| `bg-yellow-*` | `bg-warning/14 text-warning` |
| purple / indigo / cyan / amber | `bg-info/12 text-info` 或 `bg-accent/12 text-accent` |

> **陷阱**：`hover:bg-gray-200` 若也映射到 `bg-surface-2`，会和元素本身的 `bg-surface-2` 撞成同值，hover 直接失效。hover 档必须映射到 `bg-line/60`。

其余规则：
- 变体前缀（`hover:` `focus:` `md:`）与透明度后缀（`/80`）保留；语义色用 `<alpha-value>`，所以 `bg-white/80 → bg-surface/80` 可用
- `dark:` 只在整条 token 命中映射表时才剥离，其余保留（`dark:opacity-*`、`dark:shadow-*`、`dark:prose-invert`）
- 去重按 token 保序；同一变体槽出现 ≥2 个**映射结果不同**的 token 时不猜，输出 WARN 交人工
- `text-white` 只在同一字符串内含 accent / 彩色背景时才转 `text-accent-fg`，独立出现的一律保留并 WARN
- 剥完 `dark:` 变空的 className 只报告，不自动删属性

### 3.3 分批执行（每批一个提交）

1. **共享组件与布局** —— `ui/*`、`Modal`、`Notification`、`StateViews`、`Sidebar`、`Header`、`ErrorBoundary`、`NetworkStatus`、`PasswordStrength`、`TutorialSystem`
2. **前台** —— `pages/public/*`、`PublicHeader/Footer/Layout`
3. **后台高频页** —— `Posts`、`PostEditor`、`Pages`、`PageEditor`、`Media`、`Comments`、`Categories`、`Tags`、`Users`、`UserEditor`、`Settings`、`Menus`
4. **后台低频页** —— `SEO`、`Backup`、`Widgets`、`widgets/*`、`Help`、`Notifications`、`Roles`、`Analytics`、`Login` 等

先做共享组件与布局，是因为它们是下游的继承源；先定稿，后面批次才能在同一套 token 词汇下评审。

### 3.4 正文排版（`prose` 决策）

`prose` 类是死的，等于文章正文没有任何排版。**不引入 `@tailwindcss/typography` 依赖**，改为在 `src/styles/base.css` 写一段 `.rich-text` 规则，全部用语义 token（标题、段落、列表、引用、代码块、表格、图片）。然后把 5 个文件里的 `prose prose-lg dark:prose-invert` 换成 `rich-text`。

理由：避免新增依赖；且插件生成的 `--tw-prose-*` 变量还要额外映射才能跟随主题，不如直接写 token。

### 3.5 防回潮护栏

在阶段 3 的最后一批加 lint 级护栏，禁止 `src/` 内新增 `dark:` 变体与 `bg-gray-*` / `text-blue-*` 这类调色板类名（用 ESLint `no-restricted-syntax` 或一个 node 校验脚本）。否则阶段 4 的新 UI 会把硬编码色带回来。

## 验证

不依赖肉眼看页面（用户规则：不要操作浏览器）。

| 编号 | 手段 | 抓什么 |
|---|---|---|
| V1 | `npm run build` | 语法与构建失败 |
| V2 | `npm run lint`（记录基线，只比对新增） | 未使用变量、误伤 |
| V3 | **类名存在性审计**：postcss 解析 `dist/assets/*.css` 建 `class → {prop: value}` 索引；用与 codemod 同一个提取器抽全量 token，断言每个 token 在 CSS 中有规则或命中白名单（`group`、`enter-from-bottom`、动态候选） | 错拼、`bg-surface2`、动态拼接导致的静默失效 |
| V4 | **前后回归差分（核心）**：从 `git show HEAD:<file>` 与工作区分别抽「每个 className 的颜色签名」（按变体槽记录 bg/text/border token 集合），按 (文件, 出现序) 对齐，断言：旧有 `bg-*` 而新无 → FAIL；`text-*` 同理；base 与 hover 解析成同值 → WARN；仍含调色板名 + 数字或 `dark:` → FAIL | **「元素替换后丢了背景色/文字色」**，以及 hover 失效 |
| V5 | **对比度审计**：读 tokens.css 的 `:root` 与 `html[data-theme=dark]`，把每个元素的 bg token × text token 解析成 RGB，复用 `src/theme/apply.js` 的 luminance 思路断言 ≥4.5，明暗各跑一遍 | 「有背景但文字读不清」（V4 看不出） |
| V6 | 后端 `npm run smoke` | 新端点破坏既有契约形状 |

V3/V4/V5 的脚本与 codemod 共用同一个提取器，做完一并删除。

端到端手测路径（阶段 1、2、4 完成后）：改设置 → 前台看效果；建定时文章并把时间设为 5 分钟后 → 等调度器转正；编辑文章两次 → 看修订列表与 diff → 回滚。
