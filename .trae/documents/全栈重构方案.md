# HappyHome 全栈重构方案

## Context

HappyHome 是一个 React 19 + Vite + TailwindCSS 的博客 CMS（后台 + 前台），后端为 Node/Express + sql.js 单文件 SQLite。项目经过多轮功能叠加后积累了三类问题，已到必须集中处理的程度：

1. **多处功能实际已损坏，但表面看不出**。`DataContext` 只导出实体数组与语义化方法，但 7 个页面解构了不存在的成员（如 [Posts.jsx](file:///d:/xkx/xkx_appproj/happy_home/src/pages/Posts.jsx#L11) 取 `postsAPI`），导致置顶、取消定时等操作一点击必崩。
2. **后端有真实的安全与正确性缺陷**。[server.js](file:///d:/xkx/xkx_appproj/happy_home/backend/server.js#L58-L67) 的 `requireRole` 存在逻辑旁路（`role !== 'administrator'` 恒假），使所有管理员权限校验形同虚设；`posts` 表根本没有 `publish_date` 列，前端"定时发布"是彻底的空转；匿名访客因 `POST /api/comments` 挂了鉴权而无法评论。
3. **结构与视觉已不可维护**。[App.jsx](file:///d:/xkx/xkx_appproj/happy_home/src/App.jsx) 单文件 571 行承载全部路由，并在组件体内定义 28 个组件类型（每次渲染全树重挂载）；`services/` 下有 14 个零引用的死文件；Modal 有三套并存实现；全站 171 个 ESLint 问题。

本次重构的目标是：**先让项目真正可用，再把架构与视觉重做到底**。同时清理一处已推送到公开仓库的敏感资产泄露。

### 已确认的决策

| 决策点 | 结论 |
| --- | --- |
| 未挂载的 6 个页面（Backup/Notifications/Themes/SEO/CustomCSS/SocialShare） | 全部接入路由与侧边栏 |
| PublicSite.jsx | 独有内容合并进前台首页后删除（它是首页的 props 驱动重复实现） |
| Backup 页 | 实现真实备份功能（后端新增 `/api/backups`，含下载与恢复） |
| XSS 防护 | 引入 `dompurify` 替换现有自研黑名单过滤 |
| 敏感文件 | 取消跟踪 `.env` 与 `happyhome.db`，并轮换管理员密码与 JWT 密钥 |
| 重构深度 | 前端架构 + 后端拆分，UI 重新设计 |

## 关键设计要点

### 状态与数据层

**不引入数据请求库，也不再保留全局实体 store。** 判定依据：局域网自托管 CMS、单用户为主、低频写、每页只读 1–3 类实体，无并发写与乐观更新回滚诉求。引入 react-query 的收益（缓存失效、重试）可由 `useResource` + `useListPage` 覆盖，而代价是 13KB 依赖 + 全站 hook 二次迁移。

- 全局只保留 5 个真正全局且低频的状态：Auth / SiteSettings / Theme / Toast / Network。
- **实体数据全部下沉到 `features/*/hooks.js` 的 `useResource` 实例**，谁用谁取、卸载即释放 —— 从根上消灭"任一变更触发全量消费者重渲染"。
- `useResource` 签名与 react-query 的 `useQuery` 保持同构（`{ data, error, isLoading, refetch }`），预留未来迁移面。
- 升级判据（满足任一再评估引入 react-query）：≥3 个页面需共享同一实体的实时值；需乐观更新+回滚；单页需聚合 ≥5 个请求。

### 路由

采用 `createBrowserRouter` + **组件式 guard**（不用 loader：鉴权是客户端 token，在 loader 里读 localStorage 会引入渲染前副作用，且无 SSR 拦截需求）。

- 后台外壳收敛为两层：外层一个 `<RequireAuth>`（渲染 `<Outlet/>`）→ 内层一个 `<AdminLayout>`（渲染 `<Outlet/>`）。**21 处重复的 `<PrivateRoute>` 归零。**
- 删除 `App.jsx` 的 28 个组件体内定义的 `AdminXxx`：页面直接作为 `children`，外壳由 `AdminLayout` 承担。这是消除"每次渲染全树 unmount/remount"的关键。
- 删除 `activeMenu` state：菜单激活态改为从 `location.pathname` 派生（现存根因就是"用 state 镜像 URL"，永远无法同步）。用 `NavLink` 的 `end` 语义处理 `/admin` 与 `/admin/posts` 的前缀歧义。
- 侧边栏从 13+3 扁平列表改为五组：**内容 / 结构 / 外观 / 系统 / 其他**，6 个新页面入口落在「外观」与「系统」组。
- 页面级 `React.lazy` 分包（现管理后台首包包含全部页面）。
- **前台路由路径一个都不改**（`/page/:slug` 等已写入 DB 的 `menus.items`，改动会 404）。

### 后端安全修法（最优先）

| 问题 | 修法 |
| --- | --- |
| `requireRole` 旁路 | 改为 `requireRoles(...roles)`：`if (!roles.includes(req.user.role)) return 403`。"admin 是超集"由调用点显式声明。**这是必须最先改的一条** |
| `GET /api/users/:id` 无校验 | 加 service 层策略：本人或管理员，否则 403 |
| JWT 密钥硬编码 | 迁到 `config/index.js` 读 env。**默认沿用现值保证现有 token 零失效**，密钥轮换作为独立步骤执行（会让所有人重新登录） |
| `.env` 完全无效 | `dotenv` 未安装也未 require。安装并接入启动脚本 |
| CORS 全开放 | 白名单来自 `CORS_ORIGINS`，默认含 5173/3000/3002 |
| `dbHelpers` 拼接 SQL | 全参数化，upsert 改 `ON CONFLICT ... DO UPDATE` |

**响应契约冻结**：成功 `{ success, data, meta? }`，失败 `{ success: false, message, error: { code }, details? }`。**顶层保留 `message`**，使前端约 100 处 `err.message` 零改动。同时修正状态码不一致：`POST /api/comments` 现为「HTTP 200 + success:false」应改 400；通知类异常现为「HTTP 200 + success:false」应改 500。

**迁移机制**：`init-db.js` 与 `db.js` 的 16 张表 schema 完全重复且无迁移逻辑 —— 这正是 `publish_date` 缺失的根因（已存在的库永远不会获得新列）。改为 `db/schema.js` 唯一定义 + `PRAGMA user_version` 驱动迁移。首批只做 `ADD COLUMN` 与 `CREATE INDEX`（可逆性最优）。**迁移前强制复制 `.db.bak-<时间戳>`** —— sql.js 是整库 export + `writeFileSync`，迁移中途失败会毁库。

## UI 重做

### 设计主张：暖纸 + 墨

方向上刻意避开通用 SaaS 模板（现有代码的 `bg-gray-50` + `bg-white` + `shadow-sm` + `rounded-xl` + 紫蓝渐变正是最强的 AI 感来源）：

- **背景不是纯白**：亮色基底 `#FAF7F2`（暖白/纸色），卡片 `#FFFDFA`。
- **暗色不是蓝黑**：`#16130F` / `#1E1A15`（偏棕的暖炭），而非 `#0F172A`（AI 模板暗色的默认答案）。
- **强调色单一**：赭石橙 `#B4552C`（主按钮/链接/当前项/图表主色）。与暖纸基底同属暖色系，血缘最近但饱和度足够形成层级。
- **语义色降饱和**：墨绿 `#2F6B4F` / 赭黄 `#A9761B` / 砖红 `#A83A2A` / 靛青 `#35586B`。禁用 `#10B981`/`#3B82F6` 这类荧光色。
- **禁止任何渐变**，特别是 `from-*-400 to-*-500`。
- **字体**：移除 Google Fonts 的 Inter（无中文字形，中文实际 fallback，字形不统一，且本身是 SaaS 默认字体）。改用系统字体栈 `ui-sans-serif, system-ui, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` —— 零网络请求、中文有真字形。数字统一 `tabular-nums`。
- **正文基准 15px**（中文密集后台一屏多约 8% 内容），行高 1.55；标题行高 1.25。
- **圆角偏小**：小控件 8px / 默认 10px / 容器 12px。刻意不做 `rounded-2xl` 气泡感（"纸"意象对应偏小圆角）。
- **阴影用半透明而非实线边框**：`0 4px 12px -2px rgb(24 20 16 / 0.10)`；暗色下阴影更弱，改用 `inset 0 0 0 1px rgb(255 255 255 / 0.06)` 内描边。

### 动效规则

遵守 Emil Kowalski 设计工程标准，并叠加你的禁令（**只允许自下而上入场，禁止横向滑动、禁止缩放**）：

| 项 | 规定 |
| --- | --- |
| 曲线 | `--ease-out-strong: cubic-bezier(0.23, 1, 0.32, 1)`（唯一入场曲线）；`--ease-in-out-strong: cubic-bezier(0.77, 0, 0.175, 1)`。**禁用 `ease-in`** |
| 时长 | hover/press 120ms；popover/tooltip 140ms；dialog/toast 180ms；区块入场 220ms；**硬上限 300ms** |
| 按压 | `:active` 时 `scale(0.97)`，`120ms ease-out-strong` |
| 入场 | **统一 `opacity: 0 + translateY(6px)` → `0/1`**，配 `@starting-style`。绝不从 `scale(0)` 起 |
| 揭示范式 | `clip-path: inset(100% 0 0 0)` → `inset(0)`（自下而上揭示，不属缩放/横向） |
| 实现方式 | 用 CSS transition 而非 `@keyframes`（保证可中断） |
| 弹窗 | Dialog 遮罩 `opacity` + 面板 `translateY(8px→0)`，`transform-origin: center` |
| Toast | 底部区域 `translateY(10px→0) + opacity`。**现有 `animate-slide-in` 是横向的，必须删** |
| Popover/Dropdown | `transform-origin` 锚定触发点 |
| 禁用 | `translateX` 位移、`scale` 入场、`scaleX/scaleY` 展开、横向路由转场、缩放脉冲 |
| 无障碍 | `prefers-reduced-motion: reduce` 时全部降级为淡入 |

### Token 落地与全站换肤杠杆

**唯一真源是 CSS 变量，Tailwind 只做变量到工具类的映射。**

- Tailwind 色板必须是**空格分隔三元组 + `<alpha-value>`**（`'rgb(var(--c-bg) / <alpha-value>)'`），否则 `bg-accent/10` 这类透明度修饰符失效 —— 这是最容易踩的坑。
- **高杠杆技巧**：在 `extend.colors` 里**覆盖 Tailwind 内置的 `gray` 与 `primary`**（改为暖灰/赭石变量阶）。全站既有数百处 `bg-gray-50`/`text-gray-600` **无需改一行 JSX 就变成新配色**。这把 UI 重做从"改 60 个文件"降为"改 1 个配置文件 + 逐页精修"。
- `darkMode` 从 `class` 改为 `['selector', '[data-theme="dark"]']`，作用域从 `<div>` 提升到 `<html>`。**这顺带修掉一个现存 bug**：Portal 出去的 Toast/Modal 此前脱离 `dark` class 作用域，暗色下必然失真。
- `index.html` 内联同步脚本读 localStorage/`prefers-color-scheme` 设置 `data-theme` → 首屏零闪烁。
- 站点设置里的主题色通过 `SiteSettingsContext` 写 `--c-accent`，**把 Themes 页从 local state 空转变成真实可用**。

### 三个样板界面要点

- **后台列表页**：`PageHeader` → `Toolbar`（搜索/筛选/密度切换）→ `DataTable`（粘性表头、行高 48px、行尾 `…` 菜单收纳次级操作）→ `Pagination`。选中行时批量操作条以 `clip-path` 自下而上揭示。加载态用骨架屏（**不用转圈 spinner**），骨架行 stagger 20ms。
- **后台仪表盘**：刻意避开"6 个彩色 icon 方块"模板 —— 顶部一条态势摘要（36px `tabular-nums` 数字 + 12px 标签 + 半透明竖分隔线，**不用 6 种不同底色**）；主区手写 SVG 面积图（单色 accent + 半透明填充，**不引图表库、无彩虹渐变**）；右侧待处理列表；底部只读的站点健康条。数字计数 240ms（仅首屏一次），面积图用 `clip-path` 揭示。
- **前台文章详情**：滚动收缩顶栏 → 正文 `max-width: 34em`（中文约 38–42 字/行，比英文 68ch 更窄）、引用块用左侧 2px accent 竖线而非圆角气泡 → 宽屏右侧 sticky TOC（用边框宽度过渡切换，**不做滑动指示器**）→ 评论区内联展开。

**canvas-ui 评估结论**：它是 framework-agnostic 的 canvas/WebGL 组件库，只在公开前台装饰位有价值，但需处理 React 19 命令式挂载、StrictMode 双挂载幂等、ResizeObserver、`prefers-reduced-motion` 降级、不可见时暂停渲染。**放到阶段 8 作可选增强**（仅前台、`React.lazy` + 视口内才初始化）；**若集成成本超过半天即放弃**，改用零依赖替代：`SVG feTurbulence` 纸张噪点（opacity 3–5%），视觉收益接近、成本极低。
